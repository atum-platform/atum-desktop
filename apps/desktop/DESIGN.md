# Atum Desktop design overview

The client presents chats, people, agents, connected services and local execution in one desktop shell. Product copy should describe the action or state a person can understand. Keep transport names and implementation details out of ordinary user flows unless they help the person make a decision.

## Application structure

`src/app` owns routes, pages and page components. `src/store` owns shared state; feature state stays beside its feature. Shared pure helpers live in `src/lib`. Route roots compose the shell and remain thin. Prefer existing primitives and shared stores over duplicate state or deeply threaded props.

The renderer consumes the typed client contracts under `shared/`. Native services under `electron/` own local process, filesystem, credential and device boundaries. Renderer state is not authority to perform a protected native action. Preserve the existing approval, identity and ownership checks.

## Interaction

Keep the active conversation and composer stable across connection changes. Preserve unsent input and show a useful recovery action when a request cannot finish. Use the existing localization keys for all supported locales. Maintain keyboard focus, accessible names and predictable navigation.

Every surface that chooses a model uses the one two-column picker: a rail of providers and a list of the selected provider's models only. Connections are made from the rail's connect item, never from rows in the list. Atum-funded models from other makers (the OpenRouter shelf, `shared/matrix-shelf-models.ts`) get their own rail entry and appear only while the platform's offer lists them as eligible for a cloud assistant. Each row shows its price in Protons, and one that costs more than Atum's own top model carries a label rather than a confirmation step. Rows are one line, as in T3 Code's picker: the provider's (or maker's) mark before the name, then at most one muted fact (why it waits, Atum's own description, or the price), the star, and the ⌘1–⌘9 hint. When the model that answers now takes more than one thinking level that its choice can be saved with, a third column lists those levels with the model's default marked. There is no speed (Standard/Fast) control until a backend accepts one. Without that third column the card stays compact (a narrower card that shrinks to short lists and scrolls long lists within the viewport cap), so an Atum-only lineup never ships the empty column's width as empty air. A placed home's thinking level is one of the levels the platform advertises on its current model and saves with that model through the placement path; ordinary cloud conversations use the managed offer’s savable thinking levels through their existing conversation model command.

A message's "…" menu and its right-click menu are the same list: both open with the quick reactions row above Copy, and the row toggles the same native reaction the hover picker calls. It is absent while the message cannot take one, and the counts under the bubble stay the reaction chips that toggle on click. The menu’s quick reactions use native menu items, with arrow-key traversal, Enter/Space activation and checked state for your reactions. A chat row's second line is its latest message. A one-to-one chat nobody has written in yet shows the person's @handle there instead, so you can tell who it is; once the chat has any message, the row shows only the message. Handles never sit beside a name in a chat row. Find and pick surfaces (search, start chat, invite, mentions) keep the handle under every name. A status that only repeats what the transcript already shows, such as a reply having posted, is announced to screen readers and is never left as visible text; outcomes the transcript does not show (nothing ran, expired, still waiting to post) stay visible.

An assistant's card (the side panel beside its chat, or the sheet from Settings and the roster) reads like a profile (revamp 2026-11-28, `docs/plans/2026-11-28-agent-card-revamp.md`). The header is the face, the name and the @handle under it, with a "…" menu at its top right for the rare actions: change or remove the photo, rename, copy or change the @handle (the handle editor opens in a popover), choose or change its pet, and, after a separator in danger ink, delete it. Under the header sit Now while it works or waits, then at most one state notice (a save failure, not set up, off the cloud or moving, or Paused with Resume). About shows what it helps with as three lines of plain prose (`shared/matrix-assistant-about.ts`) and its Personality; Edit opens the editor sheet, the only place the persona's raw text appears. Then three small sections: On its own (Routines, whose list starts with the built-in follow-up sweep, and Pause), In this chat (Answers with, Notifications, its Pet once one is chosen, the privacy line at the foot) and Can use (Your devices, Skills). Files come last as one short list of the newest three, then Show all files. A section with nothing in it is absent. The primary assistant shows the same rows; its privileges are the Main badge, the locked name and no Delete.

Agent presentation and local/cloud placement are distinct. Read execution policy and current lease state for placement; avoid inferring ownership or availability from a display label. Display names and avatar changes must not change the underlying participant identity.

## Verification

Use focused renderer/native Vitest tests for changed behavior and the desktop typecheck for shared contracts. Tests use invented people, devices and endpoints. Service, installed-app and platform boundary checks are separate opt-in validations; a skipped check is not evidence of acceptance. See the repository contribution and security guides for reporting and contribution scope.
