# Graft T3 Code’s updater into Atum Desktop

**Decision · packaged Apple Silicon Mac · 27 November 2026 · proposed, implementation pending.** Ship T3’s actual reducer, Effect update service, React sidebar pill, Update Everything coordinator and two-call desktop handoff. The Work runtime already contains the server trial and interrupted-thread recovery code. Install one copy of the desktop graft in Electron main and mount one trusted shell control, usable even with Work closed. The signed Atum bundle remains the unit of delivery for Work, Hermes, Matrix and native helpers. A cloud agent continues running while its Mac client restarts.

**One deliberate installation difference.** In electron-updater 6.8.9 with T3’s install-on-quit setting off, MacUpdater reports the ZIP downloaded at line 219, then asks Squirrel to fetch it from the local proxy at restart at line 253. That is late for a whole Atum bundle. Take the verified ZIP from the stock downloader, prepare and assess the signed app while the old process remains usable, and keep Atum’s existing signed swap and one-generation recovery launcher as the Mac install adapter. This preserves the owner’s “load first, restart last” requirement and the recoverable signed bundle. Apple signing by itself does **not** require a custom swap. [MacUpdater 6.8.9, distributed implementation](https://unpkg.com/electron-updater@6.8.9/out/MacUpdater.js)

## How the host supplies T3’s dependencies

Atum Desktop already ships React 19, nanostores and Vitest. At D neither the desktop/root manifests nor the npm lock declare an Effect runtime for the shell. The separate Work binary cannot satisfy JS imports in Electron. Add the matching T3 catalog pins to the vendored package boundary: `effect`, `@effect/platform-node` and `@effect/atom-react` **4.1.5**. Use the matching test layer or a Vitest entry-point adapter for T3's patched vite-plus test imports. Resolve T3 contracts/shared/client-runtime from the same source snapshot, bundle the used exports and inspect both main and renderer output. Keep Atum’s existing store elsewhere. **Two different prepare/commit pairs.** (1) A permitted remote client asks the Work server to update the desktop. The server requests preparation over the local control FD. Electron returns ready-to-install plus a token. Only after receiving it does the client send server.commitDesktopUpdate. (2) During the bundled Work replacement, the *trial child* finishes migrations, acquires dependencies, binds HTTP, parks its roots and sends prepared(updateId). ## UX and the restart boundary

- Check 15 seconds after startup and every four hours in the background. Checking alone moves no bytes beyond feed/metadata. The idle pill also permits a manual check. Mirror all eight desktop states: disabled, idle, checking, up-to-date, available, downloading, downloaded and error. Installing/countdown are actions or run phases, not extra wire states. Keep release notes, progress, check animation, retry copy, confirmation and post-launch result from the graft. Replace product names/links in all supported locales. Use the same accessible names and disabled/focus behavior.
- A local Download action fetches and stages. A local Restart action confirms the interruption and installs the expected version. Atum’s regular Quit just quits. T3 sets both autoDownload and autoInstallOnAppQuit false. Its explicit versioned install path may recheck/download a requested version. Preserve the action’s target. Import the compatible U missing-cache and superseded-download changes **with their tests** as a recorded overlay on W if needed for ZIP-backed installs. Test readiness against the actual sealed stage when it is the install input. [Upstream installer](https://github.com/pingdotgg/t3code/blob/14ae67a9a80f44ccf158d2fbcc957241eec57f74/apps/desktop/src/updates/DesktopUpdates.ts#L1004)
- **Update everything** presents actual targets, affected machines/threads and provider updates. Its confirmation starts local download and eligible server staging alongside provider updates, then applies server updates, waits for handoffs and restarts the desktop last when its download is ready. The five-second countdown can be postponed. Preserve partial failures, per-machine retry and the reconnection result. A local bundled Work server, Hermes/Python, Matrix and Mac helpers arrive with the app and are counted once. T3 normally shares a release version between its desktop and server. Atum’s shell and Work pins are independent. Resolve each remote target from the signed release manifest or its own supported release catalog before passing it to the T3 collector. Never send an Atum shell version as a T3 server package version. If no compatible mapping exists, show the existing skipped-target reason. Only independently updatable, permitted targets belong in the server/provider list. Ordinary cloud agents are never targets of the Mac update.
- **Atum-specific deferral** applies at the destructive boundary for *all* entry points including remote commit and countdown expiry. Add a narrow admission callback immediately before T3 sets quitting/writes markers/stops pooled owners. Fence new local admissions, verify identity, stage seal and owner receipts under the fence. Release it and return a visible retryable reason if an owner cannot safely stop. Clear the intent on account/target change. A clean retry needs a fresh target check. This is the only extra user-visible interruption for a healthy release. Keep normal Quit available. T3's confirmation already warns that tasks can be interrupted. It cannot guarantee an ordinary shell or another application's pending side effect will survive.
- **Default decision:** match T3’s action-triggered download. Automatic checks, preparation after one click, eligible thread resume and Update Everything’s countdown provide the automatic parts. Turning on unattended downloads changes the requested UX and consumes bandwidth/disk without that click. Reserve such a preference for an explicit later change. Keep restart tied to a user-authorized action.

## Owner questions and proposed defaults
