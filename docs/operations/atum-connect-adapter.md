# Atum Connect desktop adapter

Partly built, not live. `electron/work/connect.ts` accepts an explicit `enabled:true`; default is off. Relay and platform endpoints must be HTTPS origins without credentials/query/hash/path. An injected existing Atum native bearer signs POST `/api/work/connect/assertion` with redirects refused; returned assertion stays in memory and is discarded on account switch. `requireNewDeviceApproval:true` is the required activation policy, not proof that the native server default has already been configured.

The adapter produces `getAssertion()` and `relayUrl`; native `ManagedRelayClient` methods currently name the identity input `clerkToken`. Supply the assertion there, retain native DPoP token store/proof key and exchange. The runtime web client still owns Clerk-managed authentication today. This file is a fixture-ready adapter, not wired to runtime IPC/browser auth; do not enable it or describe the default-off feature as working in the installed app. Next: wire a narrow host-owned identity adapter to native runtime managed auth, build-time relay URL, account-scoped token cleanup and one-time approval without exposing MAS/provider credentials to the Work renderer. No invented environment variables are forwarded to an unchanged runtime.
