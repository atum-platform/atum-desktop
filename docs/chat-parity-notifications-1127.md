# Portable chat notifications

Desktop slice S3 is built locally. Release acceptance still requires an installed desktop, the phone slice, and the homeserver push gateway.

Desktop uses the SDK’s push-rule operations for the four choices in the chat and channel menus. All writes a room rule with the notify action. Mentions & keywords writes an empty room rule, so higher-priority mentions and keywords can still match. Off writes an empty override scoped to the room, ahead of the default mention rules. Restore default removes the room mode and shows the inherited Matrix default for the room’s encryption and member count. Rule updates from other clients arrive through synced account data. Existing mute controls use Off and Restore default. Old room-kind mute rules display as Mentions & keywords because that is how Matrix evaluates them.

Atum requires an SDK notify decision before it offers a desktop notification. Team Space quiet hours and thread preferences can suppress eligible notifications. The former Team Space account level supplies the default for threads. Room-level delivery follows the homeserver. Legacy channel Mentions and Off still narrow presentation when the room has no explicit push rule. On the next room-mode choice for that channel, Atum saves the native mode and retires the legacy setting with the existing per-channel inherit record. Other channel and thread preferences remain intact. There are no migration writes at sign-in.

The desktop uses the existing menu and a short caveat for encrypted mentions. It preserves separate compound custom overrides that serve purposes beyond setting a room mode. The Matrix endpoints update rules individually. Atum writes the new mode before removing a competing rule and re-reads the rules on retry, so a failed switch away from Off can leave the room quiet until retry or sync.
