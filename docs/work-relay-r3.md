# Relay questions and plan usage

The R3 work continues the R1/R1s relay. A native user-input request on the active owner-DM run can be answered in chat by replying to the assistant's question. The gate checks the existing relay grant, consent, run, session, binding, reset epoch and stop state. It reads the native question through `t3_pending_request` and independently reads both sides of the Matrix reply relation. It derives structured answers from the owner's text, claims the answer event in the existing ledger, and freezes its mapping before native response. Replays use the same native request and answer. Approval requests remain in Work.

The capture supports one active native request at a time and presents its ordered fields and available choices. A single question takes a plain reply. For multiple fields, send one line per question in the displayed order, with optional numbering. Multiple selections are comma separated. Unrepresentable requests, simultaneous pending requests and scheduled questions remain in Work. If another request arrives while a reply is pending, that reply stays held. Questions in chat use the model's own wording. The original run stays open until its usual receipt is terminal.

Settings reuses the Work owner session and T3's loopback config read. It projects ChatGPT and Claude on their default instances, using the highest-utilization account-wide window still current. Only confirmed scheduled runs on this Mac inside that provider window are counted. The date and clock time stay visible for longer windows. Missing reset or duration values leave the count unavailable. Usage stays informational and off the chat status line. Rows reuse the existing Connections and Work Settings Kit pattern and shared localized usage copy.

Local checks covered 468 Electron tests with 8 live-runtime skips, 48 UI tests, the desktop typecheck, focused lint and the cross-account boundary. The tests cover wrong room and assistant anchor, approval isolation, exact native response, lost response acknowledgement, run and event replay, rollover bounds and narrow Settings copy. The existing query pack and native T3 source were checked against the pinned revision.

Signed acceptance remains open for RT10 (authentic Matrix replies through the real route), RT12 (Settings light/dark and narrow layouts), RT14 (lost/replayed transport acknowledgements across processes), RT15 (physical sleep, wake, and Stop ordering), and RT17 (installed gate boundary). Real Codex/Claude provider reporting and rollover on the paired owner session are also pending. Local scope excludes the O12 offline action, Mac release and model expansion.
