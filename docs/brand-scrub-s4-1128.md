# Desktop release branding

The desktop product presents Atum in the native shell and around agent startup,
recovery, account status, and model and tool settings. Remote setup describes
the executable and connection rather than prescribing an upstream installer.
The managed provider page omits the unconfigured external subscription. It
shows a neutral account label when the existing account is connected or current.
The provider's identity, saved state and credentials still belong to that service.

The canonical build checks generated chat, settings and pet HTML and JavaScript
before bundling the native process. The scanner checks decoded literals and
static concatenations, reports unmapped matches, and uses source maps to scope
exceptions. The renderer allowlist is exact source path plus value. Entries
cover private CSS names and selectors, storage and event keys, runtime/provider
discriminators, and the custom-endpoint review source recorded in the connection
catalogue. Mapped dependency code is outside the first-party literal check.
The locale fixture covers five desktop locales and allows the exact Matrix
protocol setup labels and example homeserver. Legal attribution uses the existing
packaged notices inventory and hash audit. No legal copy is exempt in renderer
HTML or in the locale fixtures.

The shipped updater follows the Atum feed. The development checkout updater,
app identity, private paths, IPC, credential storage, and protocol fields retain
their existing contracts. Boot errors use localized recovery copy when older
backends include a private runtime path. Detailed logs remain on disk and
available through the Open Logs action. Work relay chrome presents only a
typed turn state. The Work view renders the native tool timeline.

Verification uses the canonical unsigned build, focused renderer and native
tests, notices fixtures, client typecheck, lint, and the outbound public guard.
The full pre-push matrix was selected in plan mode because free disk was below
6 GiB. Signed install and upgrade checks and a packaged notices audit need the
assembled release candidate. The Work pin still needs the verified branded
archive. Run its local and relayed badge proof and check the final staged agent
in that same installed candidate.
